12.3.1 · Positional encoding

O que falta: noção de ordem

Self-attention "puro" (eq. 12.8) é equivariante a permutações — não leva em conta a ordem dos inputs $\mathbf{x}_n$. Mas em linguagem, ordem carrega significado.

significado AA mulher comeu o guaxinim.
significado BO guaxinim comeu a mulher.
Problem 12.3 — propriedade formal
$$\text{Sa}[\mathbf{X}\mathbf{P}] = \text{Sa}[\mathbf{X}]\,\mathbf{P}$$
para qualquer matriz de permutação $\mathbf{P}$ — trocar a ordem das colunas de $\mathbf{X}$ apenas reordena as saídas correspondentes, sem alterar seus valores. Isso mesmo é o problema: as duas frases acima teriam os mesmos vetores de saída, só reordenados.
12.3.1 · Absolute positional encodings

Somar uma marca de posição

A solução mais direta: somar uma matriz $\boldsymbol{\Pi}$ ao input, onde cada coluna é única e codifica a posição absoluta (Fig. 12.5 do livro).

$$\mathbf{X} \leftarrow \mathbf{X} + \boldsymbol{\Pi}$$
$\boldsymbol{\Pi}$ tem uma coluna distinta para cada posição — o padrão pode ser senoidal (fixo, escolhido à mão) ou aprendido como qualquer outro parâmetro.
Onde somar

Pode ser somada apenas nos embeddings de entrada, ou em cada camada do transformer.

Um detalhe sutil

Às vezes é somada apenas no cálculo de $\mathbf{Q}$ e $\mathbf{K}$ — não em $\mathbf{V}$.

12.3.1 · Relative positional encodings

O que importa é a distância, não o lugar

A posição absoluta de uma palavra é menos importante que a posição relativa entre duas palavras — um trecho de texto pode começar em qualquer ponto de um documento.

$$\mathbf{A}_{m,n} \leftarrow \mathbf{A}_{m,n} + \pi_{m-n}$$
Um parâmetro $\pi_{a,b}$ aprendido para cada offset entre a posição da key ($a$) e da query ($b$) — modifica a matriz de atenção somando, multiplicando, ou de outra forma.

Captura algo como "a palavra três posições atrás", em vez de "a palavra na posição 7" — mais robusto quando o mesmo texto pode ser fatiado em janelas diferentes.

12.3.2 · Motivação

Por que os produtos escalares precisam de freio

Produtos escalares podem ter magnitude grande, empurrando o softmax para uma região onde o maior valor domina completamente (Problem 12.4).

exemplo — cinco pré-ativações
$$\mathbf{z} = [-3,\ \ 1,\ \ 100,\ \ 5,\ \ -1]$$
$$\text{softmax}(\mathbf{z}) \approx [0,\ \ 0,\ \ 1,\ \ 0,\ \ 0]$$
$z_3=100$ domina inteiramente. Pequenas mudanças em qualquer $z_i$ (inclusive $z_3$) têm efeito quase nulo na saída — os 25 gradientes $\partial y_i/\partial z_j$ ficam próximos de zero. O modelo praticamente para de aprender ali.
12.3.2 · Scaled dot-product self-attention

A correção: dividir por √D_q

Escalonar os produtos escalares pela raiz da dimensão das queries/keys evita a saturação do softmax.

EQ. 12.9
$$\text{Sa}[\mathbf{X}] = \mathbf{V}\cdot\text{Softmax}\left[\dfrac{\mathbf{K}^T\mathbf{Q}}{\sqrt{D_q}}\right]$$
$D_q$ = dimensão de queries e keys (número de linhas de $\boldsymbol{\Omega}_q$ e $\boldsymbol{\Omega}_k$ — que devem ser iguais entre si).
12.3.3 · Multiple heads

H conjuntos de Q, K, V em paralelo

Em vez de um único self-attention, calculamos $H$ deles simultaneamente — cada "head" com seus próprios parâmetros.

EQ. 12.10 — para cada head h
$$\mathbf{V}_h = \boldsymbol{\beta}_{vh}\mathbf{1}^T + \boldsymbol{\Omega}_{vh}\mathbf{X}$$
$$\mathbf{Q}_h = \boldsymbol{\beta}_{qh}\mathbf{1}^T + \boldsymbol{\Omega}_{qh}\mathbf{X}$$
$$\mathbf{K}_h = \boldsymbol{\beta}_{kh}\mathbf{1}^T + \boldsymbol{\Omega}_{kh}\mathbf{X}$$
Mesma matriz $\mathbf{X}$ de entrada para todas as heads — só os parâmetros $\{\boldsymbol{\beta}_{\bullet h},\boldsymbol{\Omega}_{\bullet h}\}$ diferem entre elas.
12.3.3 · Multiple heads

Cada head roda seu próprio scaled attention

A mesma eq. 12.9 de antes, aplicada de forma independente dentro de cada head.

EQ. 12.11
$$\text{Sa}_h[\mathbf{X}] = \mathbf{V}_h\cdot\text{Softmax}\left[\dfrac{\mathbf{K}_h^T\mathbf{Q}_h}{\sqrt{D_q}}\right]$$
Parâmetros $\{\boldsymbol{\beta}_{vh},\boldsymbol{\Omega}_{vh}\}$, $\{\boldsymbol{\beta}_{qh},\boldsymbol{\Omega}_{qh}\}$, $\{\boldsymbol{\beta}_{kh},\boldsymbol{\Omega}_{kh}\}$ — distintos para cada head $h$.
12.3.3 · Multiple heads

Concatenar e recombinar

As saídas das $H$ heads são empilhadas verticalmente, e uma transformação linear $\boldsymbol{\Omega}_c$ as recombina (Fig. 12.6).

EQ. 12.12
$$\text{MhSa}[\mathbf{X}] = \boldsymbol{\Omega}_c\big[\text{Sa}_1[\mathbf{X}]^T,\ \text{Sa}_2[\mathbf{X}]^T,\ \dots,\ \text{Sa}_H[\mathbf{X}]^T\big]^T$$
Se a entrada tem dimensão $D$ e há $H$ heads, tipicamente values/queries/keys de cada head têm tamanho $D/H$ — o que torna a implementação eficiente (Problem 12.5).

Múltiplas heads parecem necessárias para o self-attention funcionar bem na prática — especula-se que tornam a rede mais robusta a más inicializações.

12.4 · Transformer layers

A camada completa, peça por peça

Self-attention é só uma parte. A camada transformer soma multi-head attention e uma rede totalmente conectada (aplicada a cada token separadamente), cada uma como bloco residual, com LayerNorm depois de cada uma (Fig. 12.7).

12.4 · Transformer layers

A camada completa, em quatro linhas

LayerNorm normaliza cada embedding usando estatísticas calculadas ao longo das suas próprias $D$ dimensões — diferente de BatchNorm, que usa estatísticas do batch.

EQ. 12.13
$$\mathbf{X} \leftarrow \mathbf{X} + \text{MhSa}[\mathbf{X}]$$
$$\mathbf{X} \leftarrow \text{LayerNorm}[\mathbf{X}]$$
$$\mathbf{x}_n \leftarrow \mathbf{x}_n + \text{mlp}[\mathbf{x}_n] \qquad \forall\, n \in \{1,\dots,N\}$$
$$\mathbf{X} \leftarrow \text{LayerNorm}[\mathbf{X}]$$
Os vetores-coluna $\mathbf{x}_n$ são tomados separadamente da matriz completa $\mathbf{X}$ para a etapa do mlp — a mesma rede é aplicada a cada token, independentemente. Numa rede real, os dados passam por uma série dessas camadas.

Fechamento

O que fica de pé até aqui

Temos agora um bloco transformer completo: positional encoding devolve a noção de ordem, scaled dot-product evita a saturação do softmax, multi-head permite capturar diferentes tipos de relação em paralelo, e a camada com resíduos + LayerNorm é estável o suficiente para empilhar muitas vezes.

Ficou de fora, de propósito: como esse bloco se encaixa num pipeline de NLP completo — tokenização, embeddings e os três tipos de modelo (encoder, decoder, encoder-decoder) que o resto do capítulo constrói em cima disso.
