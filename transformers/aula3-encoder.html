12.5.3 · Transformer model

Três formas de usar as mesmas camadas

Tokenização e embeddings (aula 1) produzem a matriz $\mathbf{X}$. Ela passa por uma série de $K$ camadas transformer — chamada de transformer model. O que muda entre os três tipos é como as camadas atendem umas às outras e o que se faz com a saída.

Encoder

Transforma o texto numa representação rica, reaproveitável em várias tarefas. Todo token atende a todo token.

Decoder

Prevê o próximo token da sequência. Cada token só atende a si mesmo e aos anteriores. Assunto da Aula 4.

Encoder-decoder

Combina os dois para tarefas sequência→sequência, como tradução. Também na Aula 4.

Hoje: encoder, usando BERT como exemplo concreto (seção 12.6).

Lembre-se: cada camada preserva a forma $D \times N$ da entrada — é exatamente isso que permite empilhar quantas quisermos, uma alimentando a próxima.

Todo token conversa com todo token

Num encoder, a self-attention é aplicada sem nenhuma restrição: cada posição pode atender a qualquer outra posição da sequência — inclusive as que vêm depois dela (contexto bidirecional).

12.6 · Encoder model example: BERT

BERT em números

BERT é um encoder concreto — um exemplo de tamanho real das quantidades que vimos nas aulas anteriores.

Vocabulário & embeddings

30.000 tokens no vocabulário, cada um convertido num embedding de dimensão D = 1024.

Camadas & heads

24 camadas transformer, cada uma com self-attention de 16 heads.

Dimensões internas

$\Omega_{vh},\Omega_{qh},\Omega_{kh}$ são 64×1024 (D/H = 1024/16 = 64). MLP com camada oculta de 4096.

Total: ~340 milhões de parâmetros — enorme quando o BERT foi lançado (2018), pequeno perto dos modelos de hoje.

12.6.1 · Pré-treinamento

Aprender sem rótulos: prever a palavra escondida

A auto-supervisão do BERT: substituir aleatoriamente algumas palavras por um token genérico <mask> e pedir ao modelo que recupere a palavra original a partir do embedding de saída daquela posição.

Figura 12.10 — Prince, Understanding Deep Learning (2023)

O embedding de saída na posição do <mask> passa por um softmax sobre o vocabulário inteiro — perda de classificação multiclasse.

12.6.1 · Pré-treinamento

A escala do pré-treinamento

A auto-supervisão permite usar quantidades enormes de texto não rotulado — o "custo" é que cada token processado só contribui para a perda ocasionalmente.

Dados & sequência

Máx. 512 tokens por entrada · corpus de 3.3 bilhões de palavras.

Treinamento

Batch de 256 · 1 milhão de passos · ≈ 50 épocas.

Tarefa secundária

Classificar se duas frases eram adjacentes no texto original — ganho apenas marginal.

Ineficiência de dados: são necessários 7 tokens processados para gerar apenas 2 termos na função de perda (só as posições mascaradas contam).

12.6.1 · Pré-treinamento

O que prever palavras ausentes ensina

Para prever bem a palavra escondida, o modelo é forçado a absorver regularidades de sintaxe e algum "senso comum" superficial sobre o mundo.

O <mask> entrou na estação.
P(trem | contexto) >> P(amendoim | contexto)

Também aprende regularidades sintáticas — por exemplo, que o adjetivo vermelho aparece com frequência antes de substantivos como casa ou carro, mas nunca antes de um verbo como gritar. Ainda assim, o quanto esse tipo de modelo realmente "entende" o mundo é limitado.

12.6.2 · Fine-tuning

Especializar um modelo genérico

Depois do pré-treinamento, os mesmos pesos são reaproveitados (transfer learning): acrescenta-se uma camada extra — linear ou um pequeno MLP — para converter os embeddings de saída no formato da tarefa desejada, e ajusta-se tudo com um conjunto de dados rotulado, bem menor.

Encoder pré-treinado
pesos gerais de linguagem
→
Camada de tarefa
linear / MLP + softmax ou sigmoid

Os três exemplos a seguir mostram a mesma ideia aplicada a três formatos de saída diferentes.

12.6.2 · Fine-tuning

Classificação de texto: o token <cls>

Um token especial <cls> é colocado no início de cada sequência (já durante o pré-treinamento). Para classificar a sequência inteira, usa-se só o embedding de saída dessa posição.

Figura 12.11a — Prince, Understanding Deep Learning (2023)

Exemplo — análise de sentimento: o vetor de <cls> é mapeado para um único número e passado por uma sigmoid, contribuindo para uma perda de entropia cruzada binária (positivo / negativo).

12.6.2 · Fine-tuning

Classificação por palavra: NER

No reconhecimento de entidades nomeadas, cada embedding $\mathbf{x}_n$ (não só o <cls>) é mapeado para um vetor $E\times 1$, um valor por tipo de entidade possível.

Figura 12.11b — Prince, Understanding Deep Learning (2023)
$$\mathbf{x}_n \ \longrightarrow\ \text{softmax}\big[\ \text{pessoa, local, organização, nenhuma}\ \big]$$
Cada uma das $N$ posições gera sua própria distribuição de probabilidade e seu próprio termo de perda — diferente da classificação de sequência, que usa só uma posição.
Fechamento

Encoder: representação, não geração

Um encoder como o BERT constrói uma representação bidirecional do texto, pré-treinada por auto-supervisão (prever palavras escondidas) e depois especializada por fine-tuning para tarefas específicas — classificação e NER.

Na Aula 4: o decoder (GPT3) — que não constrói uma representação para reaproveitar, mas gera texto token a token — e o encoder-decoder, que combina os dois para tarefas como tradução.
