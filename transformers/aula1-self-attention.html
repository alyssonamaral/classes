12.1 · Processing text data

O capítulo abre com uma passagem de exemplo — vale ler com atenção antes das três observações que ela motiva.

12.1 · Processing text data

Dois requisitos de design

As três observações anteriores levam a duas exigências que qualquer arquitetura para texto precisa satisfazer.

Requisito (i)

Compartilhamento de parâmetros ao longo da sequência — como convolução faz espacialmente em imagens. A rede não deve "reaprender" o que significa dog a cada posição.

Requisito (ii)

Conexões entre palavras cuja força depende do conteúdo das palavras — algo que convolução, com kernel fixo, não faz.

O transformer resolve os dois simultaneamente via dot-product self-attention. É isso que vamos construir, peça por peça, a partir de agora.

12.2.1 · Computing and weighting values

O primeiro passo: computar os values

Antes de tudo, um lembrete de como é uma camada densa comum — depois, a primeira equação do self-attention.

EQ. 12.1 — camada densa padrão
$$f[\mathbf{x}] = \text{ReLU}[\boldsymbol{\beta} + \boldsymbol{\Omega}\mathbf{x}]$$
EQ. 12.2 — value do token m
$$\mathbf{v}_m = \boldsymbol{\beta}_v + \textcolor{#3548B4}{\boldsymbol{\Omega}_v}\,\mathbf{x}_m$$
Ω_v e β_v são os mesmos para todo m — o mesmo "kernel" desliza pela sequência inteira, exatamente como convolução desliza pela imagem.
12.2.1 · Exemplo concreto

"gato dorme muito" — três tokens, D = 4

m e n são índices de posição na sequência (não de features). Cada token é um vetor em $\mathbb{R}^D$;

$$\mathbf{x}_1=\begin{bmatrix}0.2\\0.9\\0.1\\0.4\end{bmatrix}$$
"gato" (m=1)
$$\mathbf{x}_2=\begin{bmatrix}0.7\\0.1\\0.8\\0.2\end{bmatrix}$$
"dorme" (m=2)
$$\mathbf{x}_3=\begin{bmatrix}0.3\\0.5\\0.2\\0.9\end{bmatrix}$$
"muito" (m=3)
$$\mathbf{v}_1=\boldsymbol{\beta}_v+\boldsymbol{\Omega}_v\mathbf{x}_1,\quad \mathbf{v}_2=\boldsymbol{\beta}_v+\boldsymbol{\Omega}_v\mathbf{x}_2,\quad \mathbf{v}_3=\boldsymbol{\beta}_v+\boldsymbol{\Omega}_v\mathbf{x}_3$$
A mesma função $f(\mathbf{x})=\boldsymbol{\beta}_v+\boldsymbol{\Omega}_v\mathbf{x}$ aplicada três vezes — pesos idênticos, resultados diferentes porque as entradas diferem.
12.2.1 · Computing and weighting values

Roteamento: a soma ponderada

Cada saída é uma combinação diferente dos mesmos values — pense nisso como "roteamento" (Fig. 12.1 do livro).

EQ. 12.3
$$\text{sa}_n[\mathbf{x}_1,\dots,\mathbf{x}_N] = \sum_{m=1}^{N} a[\mathbf{x}_m,\mathbf{x}_n]\,\mathbf{v}_m$$
Os pesos $a[\mathbf{x}_m,\mathbf{x}_n]$ são não-negativos e somam 1 (para cada n fixo).

12.2.1 · Nota sobre esparsidade

Duas escalas de crescimento distintas

Um detalhe que volta na seção 12.9 (sequências longas)

Ω_v — transformação dos values
$$\boldsymbol{\Omega}_v \in \mathbb{R}^{D\times D}$$
Escala linearmente com N — o mesmo Ω_v de tamanho fixo é reaplicado a cada token.
a[x_m, x_n] — pesos de atenção
$$N \times N \text{ pesos}$$
Cresce quadraticamente em N — um peso por par ordenado de tokens, independente de D.
12.2.2 · Computing attention weights

De onde vêm os pesos: queries e keys

Duas transformações lineares novas — mais um hypernetwork: um ramo da rede computa os pesos que o outro ramo usa.

EQ. 12.4
$$\mathbf{q}_n = \boldsymbol{\beta}_q + \textcolor{#3548B4}{\boldsymbol{\Omega}_q}\mathbf{x}_n \qquad\qquad \mathbf{k}_m = \boldsymbol{\beta}_k + \textcolor{#3548B4}{\boldsymbol{\Omega}_k}\mathbf{x}_m$$
Query "pergunta" o que este token procura; key "anuncia" o que cada token oferece — nomes herdados de information retrieval.

12.2.2 · Computing attention weights

Softmax: da similaridade ao peso

O produto escalar mede similaridade; o softmax faz as keys competirem entre si por atenção.

EQ. 12.5
$$a[\mathbf{x}_m,\mathbf{x}_n] = \textcolor{#A85F00}{\text{softmax}_m}\big[\mathbf{k}_\bullet^T\mathbf{q}_n\big] = \dfrac{\exp[\mathbf{k}_m^T\mathbf{q}_n]}{\displaystyle\sum_{m'=1}^N \exp[\mathbf{k}_{m'}^T\mathbf{q}_n]}$$
Query e key precisam ter a mesma dimensão — mas essa dimensão pode diferir da dimensão dos values.

12.2.3 · Self-attention summary

Por que este mecanismo funciona

Juntando os pedaços: linear duas vezes (values e sua combinação), mas não-linear no conjunto — por causa do produto escalar e do softmax.

parâmetros compartilhados
$$\phi = \{\boldsymbol{\beta}_v,\boldsymbol{\Omega}_v,\boldsymbol{\beta}_q,\boldsymbol{\Omega}_q,\boldsymbol{\beta}_k,\boldsymbol{\Omega}_k\}$$
Independente de N — a mesma rede lida com sequências de qualquer tamanho.
Satisfaz requisito (i)

φ é fixo, independente de N — parâmetros compartilhados ao longo da sequência.

Satisfaz requisito (ii)

A força de cada conexão (os pesos a) depende do conteúdo dos próprios tokens.

12.2.4 · Matrix form

Empilhando tudo em matrizes

Os N inputs viram colunas de uma matriz X ∈ ℝ^(D×N) — é essa forma que roda de fato em GPU.

EQ. 12.6
$$\mathbf{V}[\mathbf{X}] = \boldsymbol{\beta}_v\mathbf{1}^T + \boldsymbol{\Omega}_v\mathbf{X}$$
$$\mathbf{Q}[\mathbf{X}] = \boldsymbol{\beta}_q\mathbf{1}^T + \boldsymbol{\Omega}_q\mathbf{X}$$
$$\mathbf{K}[\mathbf{X}] = \boldsymbol{\beta}_k\mathbf{1}^T + \boldsymbol{\Omega}_k\mathbf{X}$$
$\mathbf{1}$ é um vetor $N\times 1$ de uns — só um truque para "espalhar" o bias em todas as N colunas.
12.2.4 · Matrix form

A equação que roda em produção

Softmax aplicado independentemente a cada coluna de K^T Q — essa matriz N×N de atenção é o objeto central do resto do capítulo.

EQ. 12.7 — forma explícita
$$\text{Sa}[\mathbf{X}] = \mathbf{V}[\mathbf{X}]\cdot\text{Softmax}\big[\mathbf{K}[\mathbf{X}]^T\mathbf{Q}[\mathbf{X}]\big]$$
EQ. 12.8 — notação simplificada (a partir daqui)
$$\text{Sa}[\mathbf{X}] = \mathbf{V}\cdot\text{Softmax}\big[\mathbf{K}^T\mathbf{Q}\big]$$
$\mathbf{K}^T\mathbf{Q} \in \mathbb{R}^{N\times N}$ — a matriz de atenção. Volta em masked self-attention (decoder), cross-attention e no custo O(N²) de sequências longas.
Recapitulando

A cadeia completa, eq. 12.1 → 12.8

De uma camada densa comum até a forma matricial do self-attention — em oito passos.

Fechamento

O que fica de pé até aqui

Self-attention "puro": um mecanismo não-linear, com parâmetros compartilhados, que roteia values com pesos dependentes do conteúdo — resolvendo os dois requisitos da motivação inicial.

Ficou de fora, de propósito: positional encoding, scaled dot-product (o porquê do $\sqrt{D_q}$) e multi-head attention — as três extensões que tornam este mecanismo utilizável na prática.
