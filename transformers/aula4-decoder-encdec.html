Representar vs. gerar

Mesma arquitetura de base (embeddings + camadas transformer), objetivo completamente diferente.

12.7 · Decoder model example: GPT3

GPT3: prever a próxima palavra

Arquitetura muito parecida com a de um encoder — uma série de camadas transformer sobre embeddings aprendidos. O que muda é o objetivo e (como veremos) a forma como a atenção é restringida.

GPT3 é um modelo de linguagem autoregressivo
Dado o começo de uma frase, qual é a distribuição de probabilidade sobre a próxima palavra?
12.7.1 · Language modeling

A probabilidade da frase, fatorada

A probabilidade da sequência inteira se decompõe num produto de probabilidades condicionais — cada palavra depende só das anteriores.

exemplo — "It takes great courage to let yourself appear weak"
$$Pr(\text{It})\times Pr(\text{takes}\mid\text{It})\times Pr(\text{great}\mid\text{It takes})\times\cdots\times Pr(\text{weak}\mid\text{It}\ldots\text{appear})$$
Forma geral: $$Pr(t_1,\dots,t_N) = Pr(t_1)\prod_{n=2}^{N} Pr(t_n \mid t_1,\dots,t_{n-1})$$
12.7.2 · Masked self-attention

O problema: "colar" durante o treino

Queremos processar a frase inteira de uma vez (eficiente), calculando todas as probabilidades condicionais no mesmo forward pass — em vez de um passo por token.

→Mas se toda a frase entra de uma vez, o termo $\log Pr(\text{great}\mid\text{It takes})$ teria acesso não só à resposta great, como também ao contexto à direita: courage to let yourself appear weak.
→O modelo "colaria" em vez de aprender a prever — e nunca treinaria de verdade.

Solução: já que os tokens só interagem entre si nas camadas de self-attention, basta impedir que uma posição atenda às posições futuras.

12.7.2 · Masked self-attention

Como a máscara é aplicada

Antes do softmax, os produtos escalares que ligariam uma posição a tokens futuros são forçados a $-\infty$ — o que faz o softmax atribuir peso zero a eles.

$$a[\mathbf{x}_m,\mathbf{x}_n] = \text{softmax}_m\Big[\mathbf{k}_\bullet^T\mathbf{q}_n\Big], \qquad \mathbf{k}_m^T\mathbf{q}_n \leftarrow -\infty \ \text{ se } m>n$$
$m$ = posição da key (candidata a ser atendida), $n$ = posição da query (quem está consultando). Zerar o peso das posições $m>n$ é exatamente o mesmo mecanismo do softmax — só muda o input antes dele.
Comparando · matriz de interação

Encoder vs. decoder, lado a lado

A máscara transforma a matriz de interação num triângulo: cada posição só "vê" a si mesma e o que veio antes.

Encoder — bidirecional
Decoder — causal (mascarado)
linha = query (m) · coluna = key (n) · azul = atenção permitida
12.7.2 · Masked self-attention

Treinando o decoder, de ponta a ponta

Cada embedding de saída representa "uma frase parcial" — e o objetivo, em cada posição, é prever o próximo token de verdade.

<start> + tokens → embeddings
↓
Camadas transformer (masked self-attention) × K
↓
camada linear → tamanho do vocabulário
↓
softmax → probabilidades

Perda: entropia cruzada multiclasse somada em todas as posições — cada palavra da frase contribui um termo, tornando o treino bem mais eficiente em dados que o mascaramento do encoder.

12.7.3 · Generating text from a decoder

Gerar: o primeiro modelo generativo do curso

Como o decoder define uma distribuição de probabilidade sobre sequências, dá para amostrar dele — gerando um token, anexando-o à sequência, e repetindo.

<start> → It → takes → great → …
Escolhendo o token

Token mais provável (greedy), amostragem da distribuição, beam search (mantém várias hipóteses) ou top-k sampling (só entre os k mais prováveis).

Eficiência

Como o masked self-attention faz os embeddings anteriores não dependerem dos posteriores, boa parte do cálculo já feito pode ser reaproveitado a cada novo token.

Ponte · 12.8

E quando o objetivo é traduzir?

Um decoder puro só continua uma sequência na mesma língua/domínio. Tarefas sequência→sequência — como tradução — precisam condicionar a geração em outra sequência inteira: a frase de origem.

"The cat sat on the mat." → "Le chat s'est assis sur le tapis."
tradução = tarefa sequência-para-sequência
12.8 · Encoder-decoder model example: machine translation

Um encoder para ler, um decoder para escrever

O encoder processa a frase de origem (inglês) e produz uma representação. O decoder gera a frase de destino (francês) token a token, usando masked self-attention — mas também atendendo à saída do encoder.

Cross-attention

Queries do decoder, keys e values do encoder

O fluxo de cálculo é idêntico à self-attention comum — só muda de onde vêm $\mathbf{Q}$, $\mathbf{K}$ e $\mathbf{V}$.

encoder-decoder attention (cross-attention)
$$\mathbf{Q} = \boldsymbol{\beta}_q\mathbf{1}^T + \boldsymbol{\Omega}_q\,\mathbf{X}_{\text{dec}} \qquad \mathbf{K},\mathbf{V} = f\big(\mathbf{X}_{\text{enc}}\big)$$
$\mathbf{X}_{\text{dec}}$ carrega a estatística da língua de destino; $\mathbf{X}_{\text{enc}}$ carrega a estatística da língua de origem. Cada palavra francesa "pergunta" (query) e o inglês "responde" (key/value) — é assim que a tradução fica condicionada na frase de origem inteira.
